# 編輯資料夾說明

這個資料夾裡的每個檔案，對應網站上一個固定的區塊。用 Obsidian 打開整個 `src/content` 資料夾（跟部落格文章同一個 vault），文字改 frontmatter（檔案最上面 `---` 中間那段）或內文本身，圖片直接拖新照片進來覆蓋、或改 frontmatter 裡的檔名指到新照片，改完存檔、推上 GitHub，網站重新部署後就會套用。

## 檔案對照表

| 檔案 | 對應網站位置 |
|---|---|
| 網站設定.md | 瀏覽器分頁標題、頁首 Logo、頁尾、RSS、搜尋分享卡片 |
| 首頁-Hero.md | 首頁最上方全螢幕大圖與標語 |
| 首頁-關於我.md | 首頁「關於我」區塊（大頭照＋自我介紹。2026-08-09 起不再顯示三個數字） |
| 首頁-攝影集.md | 首頁「精選攝影集」區塊的標題文字與顯示數量 |
| 首頁-顧問服務.md | 首頁「顧問諮詢服務」三張卡片 |
| About頁面.md | /about 頁面的完整內文 |
| 攝影集/ 各檔 | 首頁「精選攝影集」與 /portfolio 攝影集頁共用的相簿主題 |

## 文字怎麼改

打開檔案 → 改 frontmatter 裡的值（例如 `heading: 關於我` 直接改後面文字），或改 `---` 下面的內文段落 → 存檔即可。frontmatter 裡如果是一整排用 `-` 開頭的清單（例如 stats、services、images），代表那是「一組可以增加/刪除」的項目，複製其中一組貼在下面照格式改就能新增一筆。

## 圖片怎麼換、容量問題怎麼處理

每個圖片欄位（`backgroundImage`、`portrait`、`images` 裡的 `src`）指向同資料夾底下 `圖片/` 子資料夾裡的檔案。要換照片：

1. 把新照片拖進對應的 `圖片/` 資料夾（檔名可以跟原本不同）。
2. 把 frontmatter 裡那一行的檔名改成新照片的檔名。

**不用自己壓縮照片。** 網站用 Astro 的內建圖片處理，建置(build)網站時會自動依照實際顯示大小重新編碼、產生多種解析度與 webp 格式，所以就算直接放手機、相機拍出來的原始檔（幾 MB 到十幾 MB）也不會讓網站變慢——真正上線的是處理過的版本。唯一要注意的是：單張照片太大（例如超過 20-30MB）會讓 GitHub 推送變慢、也會讓這個 repo 越變越大，建議盡量在拍完後用手機/電腦內建功能簡單匯出縮圖版（例如長邊 3000px 內）再放進來，不是必要但比較乾淨。

## 攝影集怎麼瀏覽（2026-08-03 更新）

首頁「精選攝影集」跟新增的 `/portfolio` 攝影集頁，現在都是**雜誌翻頁**的呈現方式：畫面一次只顯示一個主題（一個相簿檔案），用滑鼠點左右箭頭、手機滑動、或鍵盤左右鍵切換到上一個/下一個主題，不再是可以點的分類標籤列。兩個地方讀的是同一份 `攝影集/` 資料，你只要在這裡改相簿內容，首頁跟 `/portfolio` 頁會一起更新。

左上角導覽列新增了「Portfolio」這個項目（英文顯示），點進去就是完整版的攝影集頁面。

**排序**：目前一樣是照每個相簿檔案裡的 `order` 數字排序（數字小的排前面）。

## 相簿內頁的兩種版型：鑲嵌／翻頁（2026-08-07 新增）

點進某一個相簿之後，照片可以用兩種方式呈現，在相簿檔的 frontmatter 用 `layout` 這一行切換：

| 寫法 | 適合的相簿 | 點進去長什麼樣 |
|---|---|---|
| 不寫，或 `layout: 鑲嵌` | 一般單張照片 | 照片依「整幅 → 半幅 → 半幅」循環，大小交錯，每張下面顯示 `alt` 當圖說。2026-08-09 起取消左右錯開，並限制每張照片最高 72% 螢幕高度，直式照片不會再撐滿整頁寬 |
| `layout: 翻頁` | 已經在別的軟體排好版、說明文字已經印在圖上的攝影集 | 一次只顯示一頁，用左右箭頭／手機滑動／鍵盤左右鍵翻頁；不做錯落排列，也不顯示圖說小字 |

例子（`攝影集/07-La Grotte de Glace La Grave La Meije.md`）：

```yaml
label: La Grotte de Glace La Grave La Meije
order: 7
layout: 翻頁
images:
  - src: 圖片/glacier-01.png
    alt: 冰洞入口指示牌與層層堆疊的冰河紋理
```

幾點補充：

- **`alt` 還是要寫。** 翻頁版型只是不把它顯示在畫面上，Google 搜尋、視障讀者的報讀軟體仍然會讀這段文字，留空會讓建置失敗。
- 翻頁版型的圖片**完整顯示、不裁切**，所以橫幅、直幅、寬幅混在同一本裡也沒問題。
- 這一行**打錯字或留空都不會讓網站壞掉**，會自動退回「鑲嵌」。

## 相簿封面 `cover`（2026-08-07 新增）

以前相簿在列表上的封面是**硬性取 `images` 的第一張**，想換門面只能把照片調到清單最前面，但這樣連帶會改掉點進去之後的觀看順序——封面和第一張被綁在一起了。現在拆開了，相簿檔的 frontmatter 多了一行 `cover`：

```yaml
label: 巴黎地標
order: 1
cover: 圖片/paris-04.jpg
images:
  - src: 圖片/paris-01.jpg
    alt: ...
```

- `cover` 只影響**列表上那塊會被裁切的封面**（首頁精選攝影集），不影響相簿內頁的照片與順序。
- 封面**不一定要出現在 `images` 裡**，可以放一張只當門面、內頁不出現的照片。
- **整行刪掉或留空也沒關係**，會自動退回舊行為（用 `images` 第一張）。
- 封面會被裁成塊面，所以挑主體在中間、不怕裁的照片效果最好。特別是 `layout: 翻頁` 那種排好版的攝影集，第一頁通常字很多，裁起來不好看，很適合另外指定一張封面。

## 首頁精選攝影集顯示幾個、怎麼挑（2026-08-07 修正）

**修掉的問題**：首頁的塊面版型是「6 個一循環」設計的（大小塊拼起來剛好填滿），但相簿累積到第 7 個之後，多出來的就會孤零零掛在最後一排、右邊留一大片空白，也就是你看到的跑位。

現在兩件事一起處理：

1. **首頁固定只露出 6 個相簿**，版面永遠是完整的。要露幾個在 `首頁-攝影集.md` 的 `featuredCount` 改（填 6 或 12 這種 6 的倍數最整齊）。
2. **超過的相簿不是被埋掉，而是輪流露出**：每次網站重新建置（也就是你推上 GitHub、重新部署的時候），會從所有相簿裡**隨機挑一批**放上首頁，所以每次部署首頁的組合都不一樣，冷門主題也輪得到。挑出來之後仍然照 `order` 排列，版面節奏不會亂跳。
3. `/portfolio` 頁**一直都列出全部**，一個都不會漏。

**2026-08-09 更新**：`/portfolio` 不再跟首頁長得一樣了。以前兩頁都是同一組大小不一的塊面，點「View All Series」會像沒換頁；現在 `/portfolio` 改成**等寬雙欄圖卡**——每個主題一樣大（統一 4:3），主題名排在圖片下方而不是壓在圖上。兩頁的分工變成：首頁負責「這裡有東西可看」，`/portfolio` 負責「挑一個主題進去」。

**聯絡方式（2026-08-09）**：頁尾與手機選單原本有 Instagram / Facebook / YouTube / Pinterest 四個連結，但網址都還沒填、點下去停在原地，先全部收起來了，現在只留 email（explore0305@gmail.com）。之後社群帳號開好，把網址填進 `src/consts.ts` 的 `SOCIAL_LINKS` 就會自動出現。

**內容保護（2026-08-09）**：照片按右鍵不會跳出選單、也不能拖曳另存；文章內文不能選取複製。要先知道這只擋得掉順手存圖的一般讀者——會看網頁原始碼或關掉 JavaScript 的人擋不住，網路上的圖片和文字在技術上沒辦法真正防下載。真的在意的話，照片上傳前把長邊壓到 1600px 以內會比較實際。

首頁的標題文字（`Work Overview` 那一行）本來是寫死在程式碼裡的，那是改版時參考別的版型留下來的字、不是你的。現在移到 `首頁-攝影集.md`，`eyebrow`（上方小字）、`heading`（主標題）、`ctaLabel`（下方連到 /portfolio 的按鈕文字）都可以直接在 Obsidian 改。

**未來功能（尚未啟用）**：等網站對 Google 開放搜尋之後（也就是工程那邊把 `SITE_IS_PUBLISHED` 改成 `true` 的時候），規劃把上面的「隨機挑選」改成依訪客實際的點擊率、停留時間等瀏覽數據，自動把比較受歡迎的主題排到前面。這需要先另外接分析工具（Cloudflare Web Analytics 或 GA4）收集數據，目前網站還沒開放搜尋、沒有流量可以排，所以先用隨機輪替代替。之後要換只需要改挑選那一段，版面規則不用動。

## 文章標籤（tags）怎麼用

部落格文章（`src/content/blog/` 底下）frontmatter 裡的 `tags` 欄位，現在會直接顯示在網站上：文章內頁標題下方會有標籤，文章列表卡片也會顯示前三個標籤。`/blog` 頁面上方新增了「標籤」篩選列，點標籤可以快速篩到同標籤的文章；頁首搜尋視窗的「熱門搜尋」也改成自動列出目前用最多次的 5 個標籤（不用再手動維護關鍵字清單）。

標籤格式跟原本一樣，在文章 frontmatter 裡用清單寫：

```yaml
tags:
  - 露營車
  - 紐西蘭
```

**分類方式可以隨時改**：標籤清單、`/blog` 的分類篩選（依資料夾）都是從實際內容自動算出來的，不是寫死在程式碼裡。之後想新增/改名/刪除標籤，或是搬動、重新命名文章資料夾（分類依資料夾自動產生），直接在 Obsidian 改完存檔、推上 GitHub 就會反映在網站上，不用另外找工程師改程式。

## 字級層級：H1／H2／H3 是什麼意思（2026-08-09 新增）

之前版面上「哪個字比較大」是各個區塊各自決定的，所以同一個畫面會出現「區塊標題 26px、底下的文章篇名 44px」這種**下層比上層還大**的狀況——看起來就是不舒服，但說不出哪裡怪。原因就是層級被打亂了。

現在全站只有一條由大到小的階梯，每一階差約 1.25 倍：

| 層級 | 桌機大小 | 用在哪 |
|---|---|---|
| H1 | 32–52px | **一頁只有一個**。文章標題、Journal、Portfolio、相簿名 |
| H2 | 24–32px | 區塊標題。From the Journal、精選攝影集、Keep in Touch |
| H3 | 19–24px | 區塊裡的項目名。文章篇名、相簿主題名、服務項目 |
| H4 | 17–19px | 清單裡的次要標題。首頁文章目次的第 2–5 篇 |
| 內文 | 17px | 文章段落 |
| 說明 | 15px | 摘要、輔助說明 |
| 圖說 | 13px | 照片下方的圖說 |
| 眉標 | 12px | 大寫小字：Latest、日期、編號、張數 |

**判斷版面對不對的方法**：從上往下看一個區塊，字只會越來越小，不會忽大忽小。例如首頁的攝影集區是「FEATURED SERIES(12) → 精選攝影集(H2) → 相簿名(H4) → 張數(12)」，一路往下遞減。

你在 Obsidian 裡不需要指定字級，寫文章時用 Markdown 的 `##`、`###` 就好，網站會自動對到上面這條階梯（內文裡的 `#` 會比文章標題小一階，不會跟標題打架）。

## 換行規則與各欄位建議字數（2026-08-09 新增）

### 網站現在的換行邏輯

已經改成跟 Word 的中文版式一樣：

1. **標點不會跑到行首**：句號、逗號、頓號、右括號、右引號會被留在上一行的行尾（Word 的「避頭尾」）。
2. **英文單字不會被切開**：以前 `Portfolio` 可能被斷成 `Portfo / lio`，現在整個字換到下一行。
3. **標題自動平衡**：兩行的標題會被平均分配，不會出現「第一行滿滿、第二行只剩兩個字」。
4. **段落不留孤字**：段落最後一行不會只剩一個字。

這些都是自動的，你不用做任何事。

### 但是——自動換行救不了「字數本身就太多」

版面上的每個欄位都有寬度上限，超過就會多長出一行，把下面的東西往下推、破壞區塊之間的節奏。以下是各欄位的建議字數，**中文字數**（英文可以放約兩倍）：

| 位置 | 檔案 | 欄位 | 建議字數 | 超過會怎樣 |
|---|---|---|---|---|
| 首頁大圖 | 首頁-Hero.md | `eyebrow` | 英文 2–4 字 | — |
| 首頁大圖 | 首頁-Hero.md | `subtitle` | **20–30 字** | 超過 3 行會蓋住照片下緣 |
| 站名 | 網站設定.md | `title` | **4–12 字元** | 抬頭與頁尾會擠 |
| 站名說明 | 網站設定.md | `description` | **25–40 字** | 頁尾那欄會變得很長 |
| 關於我 | 首頁-關於我.md | `eyebrow` | 英文 2–3 字 | 這是該區唯一標題 |
| 關於我 | 首頁-關於我.md | 內文每段 | **40–60 字** | 段落過長會失去呼吸 |
| 關於我 | 首頁-關於我.md | `ctaLabel` | 英文 2–3 字／中文 4–6 字 | — |
| 攝影集區 | 首頁-攝影集.md | `heading` | **4–10 字** | 大字距的標題很佔寬 |
| 顧問服務 | 首頁-顧問服務.md | `heading` | **10–20 字** | 超過兩行標題會失焦 |
| 顧問服務 | 首頁-顧問服務.md | `description` | **30–38 字** | — |
| 顧問服務 | 首頁-顧問服務.md | 每項 `title` | **4–10 字** | 三欄會不等高 |
| 顧問服務 | 首頁-顧問服務.md | 每項 `description` | **20–24 字** | 同上 |
| 相簿主題名 | 攝影集/*.md | `label` | **4–12 字** | 塊面上會擠成兩三行 |
| 照片圖說 | 攝影集/*.md | `alt` | **10–25 字** | 圖說比照片還長會搶走注意力 |
| 文章標題 | 各篇文章 | `title` | **12–20 字** | 超過 20 字在列表上會被切掉 |
| 文章摘要 | 各篇文章 | `description` | **30–38 字** | 列表卡片上固定只顯示 2 行，多的看不到 |

**最容易踩到的兩個**：

- **文章標題**：目前有些篇名超過 30 字（例如「Ｎ21. 在紐西蘭和法國，四季的轉換是記憶節點，在台灣的記憶節點是年終獎金和報稅季」）。這種長度在任何版面上都會佔掉三、四行。建議把長句拆成「標題（12–20 字）＋摘要（30–38 字）」兩層——標題負責讓人想點，摘要負責交代細節。
- **文章摘要**：列表卡片上固定只顯示兩行，寫超過的部分讀者根本看不到，等於白寫。
