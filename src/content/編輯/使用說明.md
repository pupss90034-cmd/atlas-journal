# 編輯資料夾說明

這個資料夾裡的每個檔案，對應網站上一個固定的區塊。用 Obsidian 打開整個 `src/content` 資料夾（跟部落格文章同一個 vault），改完存檔、推上 GitHub，網站重新部署後就會套用。

---

## 一、先看這個：兩條編輯規則（2026-08-10 大改）

### 規則 1：會重複的項目寫在「內文」，不在屬性面板

你之前遇到的「services 在 Obsidian 點不動」就是這件事。以前顧問服務的三張卡片是寫在檔案最上面 `---` 中間的**屬性（frontmatter）**裡，長這樣：

```yaml
services:
  - title: 露營車生活諮詢
    description: 從選車、改裝到⋯⋯
```

Obsidian 對這種「清單裡面還有欄位」的結構只給你一個唯讀的屬性面板——點不進去、改不了，要動它就得切到原始碼模式跟縮排搏鬥，而且少一格空白整個網站就建不起來。

**現在改成寫在內文裡**，用你平常寫筆記的方式：

```
## 露營車生活諮詢

從選車、改裝到長途生活的日常安排，一對一整理你適合的路線與清單。
```

規則就三條：

1. 一個 `## ` 開頭的標題 ＝ 一個項目，底下那段字就是它的說明。
2. **要新增**就在最後面再打一個 `## `；**要刪掉**就整段刪掉；**要調順序**就整段剪下貼到別的位置。網站上的順序 ＝ 你在檔案裡排的順序。
3. 第一個 `##` 之前的那一段，是這個區塊的**開場說明文字**（也會顯示在網站上）。

屬性面板現在只留「一格一個值」的單行文字（標題、按鈕字樣、圖片檔名那類），那種 Obsidian 本來就編得很順。

### 規則 2：`%%` 包起來的字不會出現在網站上

```
%%
這段是寫給自己看的備忘，
Obsidian 的預覽模式看不到，網站上也不會出現。
%%
```

這是 Obsidian 原生的註解語法。以前網站不認得它，會把它原封不動印出來；2026-08-10 起兩邊一致了——**Obsidian 預覽裡看不到的，網站上也看不到**。

每個編輯檔的最下面我都用 `%%` 留了一段「這個檔案怎麼改」的說明，你在 Obsidian 編輯模式看得到，但讀者看不到。**文章裡也可以用**，例如寫到一半留 `%% 這段等查到資料再補 %%`。

## 三、Obsidian 的排序符號不會出現在網站上（2026-08-10）

你在資料夾與檔名前面加的「A - 」「Z - 」「Ｎ13.」「01 - 」是拿來控制 Obsidian 側邊欄順序的，**那是你的工具，讀者不需要看到**。網站現在會自動把它們脫掉：

| Obsidian 裡 | 網站上 |
|---|---|
| 資料夾 `A - 旅行隨記` | 分類顯示「旅行隨記」 |
| 檔案 `Ｎ13.巴賽隆納｜米拉之家.md` | 網址 `/blog/旅行隨記/巴賽隆納米拉之家/` |
| 檔案 `Ｎ16. ＿＿＿＿＿台灣的住宅文化⋯` | 那排 `＿＿＿＿＿` 佔位符號也會一起脫掉 |
| 相簿 `01-巴黎地標.md` | 網址 `/portfolio/巴黎地標/` |

**所以你可以放心改排序前綴**——想把 `A - ` 改成 `01_`、想把某個資料夾從 A 搬到 C，網站那邊都會自動跟上，不用找人改程式。

被脫掉的規則是「開頭的字母／數字 ＋ 一個分隔符號（- . 、 ．）」以及「開頭連續的底線」。文章標題本身一律以 frontmatter 的 `title` 為準，跟檔名無關。

**注意**：這次改動之後，所有文章的網址都變短了（舊網址 `/blog/a-旅行隨記/...` 不再有效）。網站目前還沒對 Google 開放收錄（`SITE_IS_PUBLISHED` 還是 false），所以現在換是最好的時機，不會有人踩到失效連結。

## 四、哪些資料夾不會上傳到網站

判斷方式是「**資料夾名稱裡有沒有這幾個字**」，不是完整名稱，所以前面加什麼排序前綴都一樣有效：

| 名稱裡含有 | 為什麼不上傳 |
|---|---|
| `模板` | 寫作用的範本，不是文章 |
| `隱藏發佈` | 寫好了但你還不想公開 |
| `未歸類` | 還沒決定放哪一區（2026-08-10 起改為不上傳） |
| `販售包` | 即將上架的付費內容，免費放上去等於送出去 |
| `Pic` | 只是放圖的資料夾 |

**另外，沒有填 `title` 的筆記一律當草稿，不會發佈**（不論放在哪個資料夾）。補上標題就會自動出現。每次建置時終端機會列出這次略過了哪幾篇。

想把某篇文章「暫時下架」，最快的方法是把 `title` 那一行清空。

## 五、販售包放在哪（2026-08-10）

`blog/Y - (販售包一) 材料包`、`(販售包二)露營車系列指南`、`(販售包三) 行程規劃器` 這三個資料夾的文章**不會**出現在 Journal 文章列表上。網站上露出的是**首頁顧問服務區底下的一段「即將上架的內容包」預告**，文字在 `首頁-販售包.md` 維護。

這樣安排的理由：三個包目前都還沒上架，如果現在就給它們一個獨立的商店頁，讀者點進去會看到一頁空的商店，反而讓人覺得這個網站沒東西。等真的有東西可以賣了，再把這一段抽出來做成獨立頁面。

想整區先收起來不顯示：把 `首頁-販售包.md` 的 `enabled` 改成 `false`。

## 六、首頁與 /blog 的新編排（2026-08-17 改版）

這次改版參考了 quietpages 這套版型的編排邏輯，但**只抄結構、不抄語彙**：字體維持 EB Garamond ＋ 思源明體，配色維持白紙墨字，沒有引入它的磚紅強調色、圓角卡片與藥丸按鈕。

### 首頁：文章從第四區搬到第二區

新的順序是：

```
封面大圖 → 文章（頭條 ＋ 三欄格線）→ 攝影集 → 關於我
        → 去過的地方 → 顧問服務／販售包 → 電子報
```

以前是「封面 → 關於我 → 去過哪裡 → 文章」，那是自我介紹的順序，適合已經認識你的人。第一次進站的讀者要的是「這裡有什麼可以讀」，先看三段自我介紹才看到第一篇文章，很多人在那之前就離開了。**先給東西看，再說自己是誰。**

文章區現在是兩段：

- **頭條（Featured）**：左邊一張 4:3 大圖，右邊是分類 · 日期 → 篇名 → 摘要 → 幾分鐘讀完 → 進入文章。右上角另有一個「All Writing →」直接到 Archive。預設抓最新發佈的那一篇；想固定某一篇，在 `首頁-最新文章.md` 的 `featuredTitle` 填幾個關鍵字就好。
- **格線（Latest）**：右上角一列分類，點一下底下就地換一批（不換頁）。最多顯示 `gridCount` 篇，預設 6。

這一區所有的字都在 `首頁-最新文章.md`。

### /blog 改名 Archive，變成可以查東西的檔案室

由上而下三樣工具：

| | 做什麼 |
|---|---|
| **搜尋框** | 邊打邊篩。篇名、摘要、分類、標籤都會找 |
| **分類／標籤下拉** | 每個選項右邊的數字 ＝「選下去會看到幾篇」，而且**跟著另一個篩選一起算**。會變成 0 的選項不會消失，只會變淡 |
| **載入更多** | 每次多顯示 `pageSize` 篇（預設 8），底下顯示「第 X / Y 頁」 |

以前是「一整列標籤按鈕 ＋ 頁碼」。文章累積到幾十篇之後，標籤列會長成一大片，而頁碼也不知道要按到第幾頁才找得到想找的那篇。

**篩選狀態會寫進網址**（`/blog?q=…&cat=…&tag=…`），所以篩完的結果可以直接複製網址傳給別人，按瀏覽器的「上一頁」會回到上一個篩選狀態，從文章底下點標籤進來也會自動套用那個標籤。

文章列表本身維持「一列一篇」：左邊文字（分類 · 日期 → 篇名 → 摘要兩行 → 幾分鐘讀完），右邊一張正方形縮圖，列與列之間一條 1px 細線，手機上自動變成圖上文下。

**「分類」＝ 這篇文章所在的資料夾名稱**（脫掉 `A - ` 這種排序前綴，見第三節）。在 Obsidian 裡把文章換一個資料夾，網站上的分類就跟著換，不用改任何設定。

### 閱讀時間（2026-08-17 新增）

「8 MIN READ」是自動算的（中文每分鐘 400 字、英文每分鐘 220 字，圖片與程式碼不計），不用自己填。不想顯示就把 `首頁-最新文章.md` 與 `頁面-文章總覽.md` 的 `showReadingTime` 改成 `false`——兩邊各自獨立。

### 標籤與地圖的分工（2026-08-10）

這兩件事現在分開了，因為它們的目的不一樣：

| | 在哪裡 | 做什麼用 |
|---|---|---|
| **標籤選單** | /blog 上方的「標籤」下拉 | **篩選工具**。點一個標籤只看那些文章，再點一次取消 |
| **足跡地圖** | 首頁，「關於我」後面 | **自我介紹**。去過的國家鋪一層淡灰，滑鼠移到右邊的地名，那個國家整塊亮起來；點下去跳到該標籤的文章 |

> 稍早（同一天下午）曾經把地圖放在 /blog 取代標籤列，傍晚改回來了。原因是篩選工具要「一眼掃完、馬上點到」，地圖做不到這件事；而地圖真正好看的地方是「這個人去過這些地方」，那屬於首頁。

### 怎麼讓一個標籤出現在地圖上

打開 `標籤地圖.md`，在下面那張表的最後一格按 Tab 就會新增一列（Obsidian 的表格可以像 Excel 一樣編輯），最少填兩格：

| 欄位 | 怎麼填 |
|---|---|
| 標籤 | 要跟文章 frontmatter 的 `tags` **一字不差**，否則對不起來 |
| 國家 | 直接寫中文國名（法國、紐西蘭⋯）。橫跨好幾國就用頓號隔開，例如 TMB 填「法國、義大利、瑞士」 |
| 緯度、經度 | **通常留空**。只有地圖畫不出來的小島才需要（大溪地就是這種，改成在海上亮一個小圈） |

幾個安心的地方：

- 表裡沒寫的標籤**不會消失**，它照常出現在 /blog 的標籤列可以點來篩選。
- 表裡有、但目前沒有任何文章在用的標籤**自動不顯示**（不會出現亮了卻沒文章的地方）。
- 國名寫錯、座標留空，都**不會讓網站壞掉**，那一列略過而已。
- 太小的國家（台灣、瑞士）光填色看不見，網站會自動幫它加一個圈。
- 地名列的順序是「文章多的排前面」，不用特地去排表格。

## 八、圖片怎麼換、容量問題怎麼處理

每個圖片欄位（`backgroundImage`、`portrait`、`cover`、`images` 裡的 `src`）指向同資料夾底下 `圖片/` 子資料夾裡的檔案。要換照片：

1. 把新照片拖進對應的 `圖片/` 資料夾（檔名可以跟原本不同）。
2. 把 frontmatter 裡那一行的檔名改成新照片的檔名。

**文章封面圖**不一樣：統一放在 `src/content/heroImage/` 資料夾（桌面上的 heroImage 捷徑），frontmatter 只寫檔名，例如 `heroImage: P1090208.JPG`，不用寫路徑。

**不用自己壓縮照片。** 建置網站時會自動依照實際顯示大小重新編碼、產生多種解析度與 webp 格式，所以直接放手機、相機的原始檔（幾 MB 到十幾 MB）也不會讓網站變慢。

> 2026-08-11 補：**文章內文的照片**以前漏掉了這層處理——它只輸出一個原始尺寸的檔案，相機直出的 6000px 照片，讀者手機上也要整張下載（一張 0.7～1.9MB）。現在跟其他照片一樣會產生多種解析度，同一張圖實際下載量降到 60～130KB。這件事在照片可以破欄、滿版之後特別重要（見下一節）。

唯一要注意的是單張超過 20–30MB 會讓 GitHub 推送變慢、repo 越變越大，建議先匯出長邊 3000px 內的版本再放進來。

## 九、文章內文的照片排版

> **2026-08-19 重訂：版面只有一種欄寬。**
>
> **文字與照片的左右邊界永遠對齊**（960px），整篇文章只有一條基準線。內文字級 20px，一行約 48 個中文字。唯一的例外是寫了 `滿版` 的照片。
>
> 之前那版做了 736 / 1152 / 滿版三種寬度，想做出「窄文字 → 寬照片 → 窄文字」的呼吸感，實際讀起來卻是版面忽寬忽窄、對不齊。節奏改用「照片前後的留白」做，不用寬度變化做。`寬`／`破欄` 還是可以寫，但效果跟不寫一樣。

### 指令一覽

在 Obsidian 裡把照片拖進文章會自動變成 `![[照片.jpg]]`，在檔名後面加 `|` 再加指令：

| 你寫 | 網站上 |
|---|---|
| `![[照片.jpg]]` | 跟文字同寬（預設） |
| `![[照片.jpg\|滿版]]` | 貼齊螢幕左右兩邊（唯一的例外） |
| `![[照片.jpg\|左圖]]` | 照片靠左佔 44%，文字排在右邊並環繞 |
| `![[照片.jpg\|右圖]]` | 照片靠右佔 44%，文字排在左邊並環繞 |
| `![[照片.jpg\|左圖大]]` | 照片佔 56%（照片是主角） |
| `![[照片.jpg\|右圖小]]` | 照片佔 34%（文字是主角） |
| `![[照片.jpg\|置中]]` | 置中（唯一會離開左基準線的一般照片） |
| `![[照片.jpg\|\|清晨六點的營地]]` | 同寬 ＋ 圖說（指令留空，兩個 `\|`） |

### 直式照片也對齊（2026-08-19）

你會偶爾丟直式照片，這件事已經考慮進去了。規則是**照片的外框永遠縮到照片本身的大小，並貼齊該側的邊界**：

| 情況 | 結果 |
|---|---|
| 橫式、一般寬度 | 撐滿 960px，左右都跟文字齊 |
| **直式**、一般寬度 | 被高度夾窄（最高 72% 螢幕高），但**左邊仍然跟文字齊**，不會跑到中間 |
| **直式** `左圖` | **左邊貼齊文字欄的左邊界** |
| **直式** `右圖` | **右邊貼齊文字欄的右邊界** |
| 橫式 `左圖`／`右圖` | 同上，寬度被 44% 夾住 |

所以不論你丟橫的還是直的，那條左（或右）基準線都不會斷。並排時的直式照片另外有一個 480px 的高度上限——旁邊還有文字要讀，照片高過一個螢幕的話那段字會被推到看不見的地方。

想讓某一張照片**置中**（例如一張刻意留白的直幅），寫 `![[照片.jpg|置中]]`。那是整篇唯一會離開左基準線的東西，用一次就好。

### 最重要的一條：照片要寫在文字「前面」

文字只能環繞排在**它前面**的照片。所以要寫成：

```
![[P1060594.jpg|右圖]]
Ps.教堂一共四面，目前還剩其中一面圍著圍籬未完成⋯
```

不要把照片放在段落的後面——那樣照片後面沒有字，沒東西可以繞。

> 網站那邊另外做了「後面沒字就往前拿一段」的補救，所以文字寫在前面也會有效果；但 **Obsidian 做不到那件事**（CSS 沒辦法把上面的字搬到照片旁邊）。要兩邊看起來一樣，就照上面的順序寫。

想結束環繞、讓後面的段落回到滿寬：中間放一個標題或一條 `---`。

### 在 Obsidian 裡就看得到（2026-08-19 新增）

不用 push 才知道效果。裝一次 CSS 片段就好：

1. Obsidian → **設定**（左下齒輪）→ **外觀**
2. 拉到最下面「**CSS 程式片段**」，按右邊的**資料夾圖示**
3. 檔案 `atlas-journal.css` 已經幫你放在 `src/content/blog/.obsidian/snippets/` 裡了，如果打開的資料夾就是那個位置，直接進行下一步；不是的話把那個檔案複製過去
4. 回 Obsidian 按**重新整理圖示**，把「**atlas-journal**」的開關**打開**

打開之後，「即時預覽」與「閱讀檢視」都會照網站的規則排版：同寬、環圖、滿版、圖說位置都一樣。之後改指令，Obsidian 裡當場就看得到。

> 為什麼兩邊做得出一樣的效果：網站的圖文並排改用 **float**（跟 Obsidian 一樣），所以文字比照片長的時候，兩邊都會自然環繞到照片下方，不會在照片底下留一塊空白。

### 圖文並排怎麼配對文字

1. 照片後面如果緊接著一個標題（`###`），它會變成那一塊的小標題。
2. 接著把後面的段落／清單一起放進同一塊，**最多三段**。
3. 遇到下一張照片、下一個標題、或一條 `---` 就停。
4. 後面完全沒有文字可以配對時，**往前拿一段**——你習慣先寫完一句話再把照片拖到後面，這樣也會生效。

```
![[照片.jpg|左圖]]
### 那天的光線

第一段說明，排在照片右邊。

第二段說明，也在同一塊裡。

---

分隔線之後回到正常的滿寬段落。
```

### 照片不用前後空一行

在 Obsidian 裡邊寫邊拖照片，最自然的結果是中間沒有空行——**這樣寫就會正確**：

```
聖家堂就是其中之一。
![[P1060560.jpg]]
有別於桂爾公園的流線設計⋯
```

會被拆成〔文字〕〔照片〕〔文字〕三塊。真的想把照片放在句子中間（前後同一行還有字），那還是行內圖，不受影響。

### 語法打錯會自動修

正確寫法只有兩種：`![[檔名.jpg|指令]]` 或 `![指令](檔名.jpg)`。手打最常漏掉括號，下面這幾種網站都認得：

| 你打成 | 網站怎麼處理 |
|---|---|
| `![右圖]P1060594.jpg` | 當成 `![[P1060594.jpg\|右圖]]` |
| `[右圖]P1060594.jpg` | 同上 |
| `![右圖][P1060594.jpg]` | 兩組方括號，也當成 `![[P1060594.jpg\|右圖]]` |
| 整行只有 `P1060594.jpg` | 當成 `![[P1060594.jpg]]` |

每修一次建置訊息都會印出正確寫法。**最保險還是用拖曳**產生 `![[檔名.jpg]]`，再補 `|指令`。

### 兩張照片並排

規則只有一條——中間有沒有空行：

```
![[A.jpg]]
![[B.jpg]]          ← 沒空行 ＝ 兩張並排成一組

![[A.jpg]]
                    ← 有空行 ＝ 上下排，各自獨立一張
![[B.jpg]]
```

並排的兩張各佔一半欄寬、底緣對齊、不裁切。手機上自動變回上下排。

### 節奏建議

整篇只有一種欄寬之後，節奏靠三件事做：**照片前後的留白**、**滿版出現的次數**、**圖文並排的位置**。滿版一篇最多一到兩次；連續三、四組左右並排會讓文章變成一張表格，建議「上下 → 左右並排 → 上下 → 滿版 → 上下」交替。

## 九之二、文章標題一律只顯示一行（2026-08-18）

以前標題太長會換行，而中文的換行位置是瀏覽器決定的——它只避開標點、不管語意，所以「史特拉斯堡｜聖誕市集飲食記」會被斷成：

```
史特拉斯堡｜聖
誕市集飲食記
```

在「｜」後面斷開，把一個詞從中間切成兩半。標題是一塊招牌，應該一眼讀完，不是一段要換行的內文。

**現在的規則：所有篇名一律一行，字級自動縮到剛好放得下。** 首頁頭條、首頁格線、Archive 列表、文章內頁的大標，四個地方都一樣。短標題維持原本大小，長標題自動縮小一點，縮到下限還是放不下的極端狀況才用「…」收尾。

這件事是自動的，你不用做任何設定。但有一個影響值得知道：**標題越長，它在版面上就越小**。所以建議仍然是「標題 12–20 字，細節放摘要」（見第十二節的建議字數表）——不是因為會被切掉，而是因為短標題看起來比較大、比較有力。

## 十、攝影集

首頁「精選攝影集」與 `/portfolio` 讀的是同一份 `攝影集/` 資料，改一次兩邊一起更新。

**首頁固定露出 6 個**（在 `首頁-攝影集.md` 的 `featuredCount` 調整，填 6 或 12 這種 6 的倍數最整齊）。相簿超過這個數量時，每次重新部署會**隨機挑一批**露出，冷門主題也輪得到；`/portfolio` 一直都列出全部。

`/portfolio` 是**等寬雙欄圖卡**（每個主題一樣大、統一 4:3，主題名排在圖片下方）。兩頁分工不同：首頁負責「這裡有東西可看」，`/portfolio` 負責「挑一個主題進去」。

### 相簿內頁的兩種版型

| 寫法 | 適合的相簿 | 點進去長什麼樣 |
|---|---|---|
| 不寫，或 `layout: 鑲嵌` | 一般單張照片 | 照片依「整幅 → 半幅 → 半幅」循環，大小交錯，每張下面顯示 `alt` 當圖說。每張最高 72% 螢幕高度 |
| `layout: 翻頁` | 已經在別的軟體排好版、說明文字印在圖上的攝影集 | 一次只顯示一頁，左右箭頭／手機滑動／鍵盤翻頁；不顯示圖說小字 |

- **`alt` 一定要寫。** 翻頁版型只是不顯示它，Google 與報讀軟體仍然會讀，留空會讓建置失敗。
- 這一行打錯字或留空都不會讓網站壞掉，會自動退回「鑲嵌」。

### 相簿封面 `cover`

```yaml
label: 巴黎地標
order: 1
cover: 圖片/paris-04.jpg
```

- `cover` 只影響**列表上那塊會被裁切的封面**，不影響內頁的照片與順序。
- 封面不一定要出現在 `images` 裡，可以放一張只當門面的照片。
- 整行刪掉或留空會自動用 `images` 的第一張。
- 封面會被裁成塊面，挑主體在中間、不怕裁的照片效果最好。

**排序**照每個相簿檔案裡的 `order` 數字（小的排前面），跟檔名前面的 `01-`、`02-` 無關——那個只是給 Obsidian 側邊欄看的。

## 十一、字級層級：H1／H2／H3 是什麼意思

全站只有一條由大到小的階梯，每一階差約 1.25 倍：

| 層級 | 桌機大小 | 用在哪 |
|---|---|---|
| H1 | 32–52px | **一頁只有一個**。文章標題、Journal、Portfolio、相簿名 |
| H2 | 24–32px | 區塊標題（From the Journal、精選攝影集、Keep in Touch），以及**首頁頭條的篇名**——那一段沒有區塊標題，篇名就是最高層級 |
| H3 | 19–24px | 區塊裡的項目名。/blog 的文章篇名、相簿主題名、服務項目 |
| H4 | 17–19px | 清單與格線裡的次要標題。首頁三欄格線的篇名、販售包項目名 |
| 內文 | 17px | 文章段落 |
| 說明 | 15px | 摘要、輔助說明 |
| 圖說 | 13px | 照片下方的圖說、地圖上的地名 |
| 眉標 | 12px | 大寫小字：Latest、日期、編號、張數 |

**判斷版面對不對的方法**：從上往下看一個區塊，字只會越來越小，不會忽大忽小。

你在 Obsidian 裡不需要指定字級，寫文章時用 `##`、`###` 就好，網站會自動對到這條階梯。

## 十二、換行規則與各欄位建議字數

網站的換行已經跟 Word 的中文版式一樣：標點不會跑到行首、英文單字不會被切開、兩行的標題會自動平衡、段落最後一行不會只剩一個字。這些都是自動的。

**但自動換行救不了「字數本身就太多」。** 各欄位的建議**中文字數**（英文可以放約兩倍）：

| 位置 | 檔案 | 欄位 | 建議字數 |
|---|---|---|---|
| 首頁大圖 | 首頁-Hero.md | `subtitle` | 20–30 字 |
| 站名 | 網站設定.md | `title` | 4–12 字元 |
| 站名說明 | 網站設定.md | `description` | 25–40 字 |
| 關於我 | 首頁-關於我.md | 內文每段 | 40–60 字 |
| 攝影集區 | 首頁-攝影集.md | `heading` | 4–10 字 |
| 顧問服務 | 首頁-顧問服務.md | `heading` | 10–20 字 |
| 顧問服務 | 首頁-顧問服務.md | `description` | 30–38 字 |
| 顧問服務 | 首頁-顧問服務.md | 每個 `##` 標題 | 4–10 字 |
| 顧問服務 | 首頁-顧問服務.md | 每段說明 | 20–24 字 |
| 販售包 | 首頁-販售包.md | 每個 `##` 標題 | 4–12 字 |
| 販售包 | 首頁-販售包.md | 每段說明 | 20–30 字 |
| 電子報 | 首頁-電子報.md | 開場短介紹 | 30–40 字 |
| 文章總覽 | 頁面-文章總覽.md | 引導小字 | 25–45 字 |
| 攝影集總覽 | 頁面-攝影集總覽.md | 引導小字 | 20–40 字 |
| 相簿主題名 | 攝影集/*.md | `label` | 4–12 字 |
| 照片圖說 | 攝影集/*.md | `alt` | 10–25 字 |
| 文章標題 | 各篇文章 | `title` | 12–20 字 |
| 文章摘要 | 各篇文章 | `description` | 30–38 字 |

**最容易踩到的兩個**：

- **文章標題**：目前有些篇名超過 30 字，在任何版面上都會佔掉三、四行。建議拆成「標題（12–20 字）＋摘要（30–38 字）」兩層——標題負責讓人想點，摘要負責交代細節。
- **文章摘要**：列表卡片固定只顯示兩行，寫超過的部分讀者根本看不到。

## 十三、其他

- **`[[筆記名稱]]` 連結**：照 Obsidian 的習慣打就好，網站上會變成真的可點連結。連到還沒發佈（沒標題、或放在不上傳的資料夾）的筆記時，不會產生死連結，只會留下文字並標記成待修，你在網站上一眼看得出來。
- **內容保護**：照片按右鍵不會跳選單、不能拖曳另存；文章內文不能選取複製。這只擋得掉順手存圖的一般讀者，會看原始碼的人擋不住——真的在意的話，照片上傳前把長邊壓到 1600px 以內比較實際。
- 這個資料夾的檔案跟部落格文章一樣都會被 commit 到 GitHub、參與網站建置，不是草稿區。
- **未來功能（尚未啟用）**：等網站對 Google 開放收錄後，規劃把首頁攝影集的「隨機挑選」改成依訪客點擊率、停留時間自動排序。這需要先接分析工具收集數據。
